- 실연동 검증 계획 승인: 현재 코드가 localhost/preview 호스트 전송을 차단하므로 미리보기 클릭을 실수신 확인으로 보고하지 않는다. 운영을 무조건 먼저 켜거나 호스트 제한을 임의 해제하지 말고, 통제된 검증 방법·데이터·중단 방법을 개발방에서 제안한다.
- 검증: 동의 전 요청 없음 → 동의 후 page_view/스토어 클릭의 단일 수신 → 철회 후 중단, 전송 필드 점검, GA4 Realtime/DebugView 확인. 일반 맞춤 보고서 반영에는 Google 안내상 24~48시간이 걸릴 수 있다. 테스트 즉시 수신과 일반 보고서 반영을 분리 기록한다.
- 사용자 배포 승인 후 승인 변경만 commit/push/deploy. 운영 HTTPS 정책 URL, 푸터, CSP, 중복 태그 없음, 수집 동작을 확인한다. 수집 중지 시에도 정책을 유지하는 되돌리기 절차를 포함한다.
- 반환물: 구현 범위와 candidate/commit, 실제 실행한 검증 증거, 미확인 항목, 배포 여부. 계획·코드 검토·모의 테스트를 실제 수신 PASS로 바꾸지 않는다.
